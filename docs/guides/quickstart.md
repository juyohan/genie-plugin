# 빠른 시작 가이드

---

## 설치 후 첫 번째 할 일

새 프로젝트 디렉토리에서 아래 커맨드를 실행합니다.

```
/genie:setup
```

실행하면 Genie가 프로젝트를 스캔하고 스택을 자동으로 감지합니다. 감지한 정보를 바탕으로 몇 가지 확인 질문을 한 뒤 `CLAUDE.md`와 `docs/` 기본 구조를 생성합니다. 이 파일들이 이후 모든 단계의 기반이 됩니다.

---

## 첫 기능 개발 흐름

### 1단계: 요구사항 정의 — `/genie:brainstorm`

"알림 일시 정지 기능을 만들고 싶어요"처럼 아이디어를 말하면 됩니다. Genie가 한 번에 하나씩 질문하며 요구사항을 구체화합니다.

```
당신: "알림 일시 정지 기능을 만들고 싶어요"
Genie: "일시 정지 시간을 사용자가 직접 설정하나요, 아니면 고정된 값(예: 1시간)을 사용하나요?"
```

완료되면 `docs/brainstorms/YYYY/MM/DD-알림-일시정지.md`에 요구사항 문서가 저장됩니다.

### 2단계: 구현 계획 — `/genie:plan`

brainstorm 결과를 바탕으로 구현 계획을 수립합니다. 어떤 파일을 만들고, 인터페이스를 어떻게 설계하고, 어떤 테스트를 작성할지 결정합니다.

완료되면 `docs/plans/YYYY/MM/DD-알림-일시정지.md`에 계획 문서가 저장됩니다. 구현 전에 이 문서를 반드시 확인하세요.

### 3단계: 테스트 작성 — `/genie:test`

plan 문서를 읽고 실패하는 테스트를 먼저 작성합니다 (RED). 구현 코드가 없으므로 테스트는 모두 실패합니다. 이것이 정상입니다.

### 4단계: 구현 — `/genie:work`

plan의 가드레일을 따라 테스트를 통과하는 최소한의 코드를 구현합니다 (GREEN). 구현 후 리팩토링까지 진행합니다 (IMPROVE). 완료 시점에 커버리지가 80% 이상인지 확인합니다.

### 5단계: 코드 리뷰 — `/genie:review`

다층 페르소나(시니어 엔지니어, 보안 전문가, 일관성 리뷰어)로 코드를 검토합니다. 리뷰 결과는 `docs/reviews/YYYY/MM/DD-알림-일시정지.md`에 저장됩니다. CRITICAL·HIGH 이슈가 있으면 커밋 전에 반드시 수정하세요.

### 6단계: 커밋 — `/genie:commit`

변경 내용을 분석하여 Conventional Commits 형식의 커밋 메시지를 자동 생성합니다. 메시지를 확인하고 승인하면 커밋이 완료됩니다.

예시 생성 메시지:
```
feat(notification): 알림 일시 정지 기능 추가

사용자가 지정한 시간(분 단위) 동안 모든 알림을 중단합니다.
재시작 없이 즉시 적용되며 앱 재시작 시 자동 해제됩니다.
```

## 자주 쓰는 에이전트 패턴

워크플로우 커맨드 외에도 언제든지 채팅에서 전문 에이전트를 직접 호출할 수 있습니다.

**코드 리뷰**: TypeScript 파일 품질·타입 안전성 검토

```
@genie:ts 이 파일 리뷰해줘
```

**빌드 에러 수정**: 빌드 실패 원인 분석 후 최소한의 수정

```
@genie:fix 빌드 에러 고쳐줘
```

**보안 감사**: API 엔드포인트 취약점 분석 (인증·입력 검증·SQL 인젝션 등)

```
@genie:security 이 API 엔드포인트 확인해줘
```

## 훅이 동작하는 걸 처음 봤을 때

설치 후 개발하다 보면 다음과 같은 메시지를 보게 됩니다.

**branch-guard 경고**
```
[보호 브랜치] 현재 브랜치: `main`
이 브랜치에 직접 작업하는 것은 허용되지 않습니다.
```
main·master·develop·staging에서 커밋·푸시를 시도할 때 표시됩니다. 새 브랜치를 만들어 작업하라는 안내입니다.

**quality-gate 자동 실행**
```
[quality-gate] biome check --write src/notification.ts
```
파일 편집 후 해당 언어의 포매터가 자동 실행됩니다. 별도로 포매터를 실행할 필요가 없습니다.

**gateguard 차단 메시지**
```
[GateGuard] 근거 없는 편집 요청이 차단됩니다.
```
코드베이스를 확인하지 않고 추측으로 파일을 수정하려 할 때 표시됩니다. Claude가 파일을 먼저 읽고 이해한 뒤 편집하도록 유도하는 품질 장치입니다. Claude가 이 메시지를 받으면 먼저 관련 파일을 읽은 뒤 다시 작업을 시도합니다.

**session-start 컨텍스트 로드**
```
[session-start] 이전 세션 컨텍스트를 로드합니다.
```
Claude Code를 새로 열었을 때 이전 세션에서 하던 작업 내용을 자동으로 불러옵니다.

**cost-tracker 기록**
```
[cost-tracker] 세션 비용: $0.042 (input: 12,453 tokens, output: 3,211 tokens)
```
세션 종료 시 이번 세션의 API 사용 비용을 기록합니다. `~/.claude/costs/`에 누적 저장됩니다.
